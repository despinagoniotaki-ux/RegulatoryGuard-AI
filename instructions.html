1  Overview

RegulatoryGuard AI is a three-tier, flat-file pre-clinical data compliance engine built for the IBM Bob 2.0 Hackathon. It automates the detection of dosing variance deviations across animal cohorts, surfaces compliance verdicts in a modern Streamlit dashboard, and generates eCTD-ready narratives via the IBM Bob 2.0 large language model API.

Architecture at a glance

TierComponentRole
1 — RulesRegulatoryGuardAI_Rules_Example.csv → regulatory_rules.jsonScience-team-authored variance thresholds per assay parameter
2 — Engineprocess_data.pyPandas engine: computes deviation %, assigns traffic-light status, maps cohort → rule
3 — UI & AIapp.py + Bob 2.0 APIStreamlit dashboard + AI narrative generation

Traffic-light compliance verdicts

INCLUDE — deviation ≤ minor limit REVIEW — between minor & major limit EXCLUDE — exceeds major limit

Key capabilities

  • Multi-project workspace with unique 15-digit project IDs
  • Per-record 15-digit IDs (first 6 digits derived from the project ID)
  • Import delta detection — new records vs. previously seen records highlighted
  • Custom rules upload (CSV or JSON) overriding the default rulebook
  • Bob 2.0 AI narrative generation with graceful placeholder fallback
  • One-click eCTD-ready CSV export

2  Installation & Setup

Prerequisites

  • Python 3.10 or later
  • pip (comes with Python) or conda
  • Git (optional — you can also download the ZIP)
  • ~200 MB free disk space
Tip: Using a virtual environment is strongly recommended to avoid dependency conflicts with other projects.

Step-by-step

  • 1
    Clone or download the project 
    git clone https://github.com/your-org/RegulatoryGuardAI.git
cd RegulatoryGuardAI
  • 2
    Create and activate a virtual environment 
    # macOS / Linux
python3 -m venv .venv
source .venv/bin/activate

# Windows
python -m venv .venv
.venv\Scripts\activate
  • 3
    Install dependencies 
    pip install -r requirements.txt
    The following packages will be installed:
    • streamlit >= 1.35
    • pandas >= 2.0
    • numpy >= 1.26
    • requests >= 2.31
    • python-dotenv >= 1.0
  • 4
    Configure watsonx.ai credentials

    Copy the example file and fill in your own values:

    cp .env.example .env
    Then open .env in any text editor and set: 
    WATSONX_PROJECT_ID=your-watsonx-project-id-here
WATSONX_API_KEY=your-ibm-cloud-api-key-here
    • Project ID — found in your watsonx.ai project settings under Manage → General.
    • API Key — create one at cloud.ibm.com/iam/apikeys.

    The app reads these values at startup and pre-fills the sidebar fields automatically. You can always override them in the sidebar without editing .env.

  • 5
    Compile the default rulebook (only needed once, or after editing the CSV) 
    python convert_rules_dynamic.py RegulatoryGuardAI_Rules_Example.csv
    This produces regulatory_rules.json at the project root.
Already done? A pre-compiled regulatory_rules.json is included in the repo — you can skip step 5 unless you modify the rules CSV.
Demo mode: The shared demo build ships with credentials pre-loaded in .env — no extra configuration is needed to try AI narrative generation. For your own deployment, replace the values in .env with your credentials.

3  Launching the Dashboard

From the project root (with the virtual environment active):

streamlit run app.py

Streamlit will print something like:

  You can now view your Streamlit app in your browser.
  Local URL:  http://localhost:8501
  Network URL: http://192.168.x.x:8501

Open http://localhost:8501 in your browser.

Port conflict? Use streamlit run app.py --server.port 8080 to run on a different port.

4  Dashboard Walkthrough

4.1 — Sidebar

The left sidebar is divided into four sections:

SectionPurpose
🗂 ProjectCreate a new project (name + description → unique 15-digit ID assigned automatically) or switch to an existing one.
📋 Compliance RulesDownload the template rules CSV; upload a custom rules file (CSV or JSON).
📂 DatasetLoad the built-in mock dataset or upload your own pre-clinical CSV.
🤖 Bob 2.0 Narrativewatsonx.ai Project ID and IBM Cloud API Key for AI narrative generation (pre-filled from .env).

4.2 — Executive Summary

After running the compliance check, four KPI cards appear at the top of the main panel:

  • Total Records — number of rows analysed in this import, with new-record delta
  • ✓ Include — records within all acceptance limits (green)
  • ⚠ Review — records between minor and major variance limits (yellow)
  • ✕ Exclude — records exceeding the major variance limit (red)

4.3 — Distribution Charts

  • Status Distribution — bar chart of INCLUDE / REVIEW / EXCLUDE counts
  • Deviation % by Cohort — mean deviation per cohort group
  • Deviation % Histogram — frequency distribution across deviation buckets

4.4 — Interactive Data Viewer

Filter the results table by:

  • Status multi-select (INCLUDE / REVIEW / EXCLUDE)
  • Cohort multi-select
  • Free-text search across Animal ID and Notes fields

Each row includes: Record_ID, Animal_ID, Cohort, Target_Dose_mg_kg, Actual_Dose_mg_kg, Deviation_Pct, Status (badge), System_Action, Applied_Rule, and Delta (NEW / EXISTING).

4.5 — Import History

Expand the Import History panel at the bottom to see a timestamped log of all compliance runs within the current session, including import IDs and new-record counts.

Project IDs and Record IDs: Every project is assigned a random 15-digit numeric ID. Each imported record receives its own 15-digit ID where the first 6 digits match the last 6 digits of the project ID, enabling traceability across exports.

5  Using Custom Rules

Download the template

Click "⬇ Download Rules Template" in the sidebar to get RegulatoryGuardAI_Rules_Example.csv. Open it in any spreadsheet editor.

CSV column reference

ColumnTypeDescription
Assay_ParametertextName of the assay (must match cohort mapping)
UnittextUnit of measurement (for display only)
Minor_Variance_Limit_PercentnumberUpper boundary of the INCLUDE zone (%)
Major_Variance_Limit_PercentnumberUpper boundary of the REVIEW zone; beyond this = EXCLUDE (%)
Action_RequiredtextAction text shown in the REVIEW row (e.g. Review / Exclude)

Upload your rules

  • 1
    Edit the CSV template with your thresholds and save it.
  • 2
    In the sidebar under 📋 Compliance Rules, use the Upload custom rules file picker.
  • 3
    A success message confirms how many rules were loaded.
  • 4
    Click "▶ Run Compliance Check" — the engine will now use your rules.
You can also upload a JSON file (.json) that already follows the regulatory_rules.json schema — the app accepts both formats.

Cohort-to-rule mapping (default)

CohortAssay Parameter Applied
Group_1_LowBody Weight Change
Group_2_MidSerum Glucose
Group_3_HighHeart Rate
Group_4_ControlAlanine Aminotransferase (ALT)

Cohorts not in this mapping fall back to the rule with the most conservative (lowest) minor variance limit.

6  Bob 2.0 Narrative Generation

RegulatoryGuard AI integrates the IBM Bob 2.0 large language model to automatically produce an eCTD Section 2.6-style compliance narrative from the processed compliance summary.

Configuration

Credentials are loaded automatically from .env at startup (see Installation & Setup — Step 4). The sidebar fields are pre-filled; you can edit them inline at any time without touching .env.

  • 1
    Ensure .env contains your WATSONX_PROJECT_ID and WATSONX_API_KEY (or enter them directly in the sidebar under 🤖 Bob 2.0 Narrative).
  • 2
    Run a compliance check ("▶ Run Compliance Check") to produce a summary.
  • 3
    Click "🤖 Generate Narrative" — the app will call watsonx.ai and display the result.
No credentials? If either sidebar field is left blank, the app will display a clearly labelled placeholder narrative — the rest of the dashboard remains fully functional.

What the narrative includes

  • Total number of records analysed
  • Per-status counts and percentages
  • Maximum deviation observed and which cohort it occurred in
  • Which assay rules were applied
  • A professional summary sentence suitable for eCTD submission

How it works

Step 1 — IAM token exchange: The app POSTs your API key to https://iam.cloud.ibm.com/identity/token to obtain a short-lived bearer token.

Step 2 — Inference call:

POST https://us-south.ml.cloud.ibm.com/ml/v1/text/generation?version=2023-05-29

Headers: Authorization: Bearer <iam_token>, Content-Type: application/json

Model: ibm/granite-13b-instruct-v2

Payload includes: project_id, model_id, input (prompt), parameters

No extra SDK — called via standard requests library.

8  Running the Pipeline Standalone

Each tier can be run independently from the command line — useful for batch processing, CI pipelines, or quick testing without opening the dashboard.

Tier 1 — Compile rules

python convert_rules_dynamic.py RegulatoryGuardAI_Rules_Example.csv
# Output: regulatory_rules.json

# Custom output path:
python convert_rules_dynamic.py my_rules.csv my_output.json

Tier 2 — Run compliance engine

python process_data.py
# Reads:  RegulatoryGuardAI_Test_Records/RegulatoryGuardAI_mock_preclinical_data.csv
#         regulatory_rules.json
# Output: audit_ready_report.csv
Expected distribution for the mock dataset: ~90% INCLUDE, ~7% REVIEW, ~3% EXCLUDE across 3,200 records.

Full pipeline (one-liner)

python convert_rules_dynamic.py RegulatoryGuardAI_Rules_Example.csv && python process_data.py

9  FAQ & Troubleshooting

The dashboard shows "No active project" after I create one

The project is stored in the Streamlit session state. If the page fully reloads (e.g. after a code change while the dev server is running), session state is cleared. Simply re-create the project in the sidebar — this is expected behaviour for the MVP's in-memory persistence.

Clicking "Load Mock Dataset" does nothing

Ensure the file RegulatoryGuardAI_Test_Records/RegulatoryGuardAI_mock_preclinical_data.csv exists relative to the directory you launched Streamlit from. Always run streamlit run app.py from the project root.

ModuleNotFoundError: No module named 'streamlit'

Your virtual environment is not active, or you forgot to run pip install -r requirements.txt. Re-activate the environment (source .venv/bin/activate) and reinstall.

Rules uploaded but compliance check still uses old thresholds

After uploading new rules, click "▶ Run Compliance Check" again. Uploading the file updates the rules in session state; the engine only uses them on the next run.

watsonx.ai narrative returns an error or empty text

  • Check that WATSONX_PROJECT_ID and WATSONX_API_KEY in .env are correct (no extra spaces or quotes).
  • Confirm the API key is valid and has not been deleted — regenerate it at cloud.ibm.com/iam/apikeys if needed.
  • Verify the project ID matches the one shown in your watsonx.ai project under Manage → General.
  • Check that your network allows outbound HTTPS to iam.cloud.ibm.com and us-south.ml.cloud.ibm.com.
  • If the issue persists, the placeholder narrative is used automatically — the app remains fully functional.

How do I add my own cohort-to-rule mappings?

Open app.py and find the COHORT_RULE_MAP dictionary near the top. Add entries in the format "Your_Cohort_Name": "Assay_Parameter_Name". The assay parameter name must exactly match the Assay_Parameter column value in your rules CSV.

I want to persist projects across sessions

The MVP uses Streamlit session state (in-memory). For persistence, export the results CSV after each session. A database backend is out of scope for this hackathon release.

Port 8501 is already in use

streamlit run app.py --server.port 8080

Python version compatibility

RegulatoryGuard AI requires Python 3.10 or later. Run python --version to verify. On macOS / Linux you may need to use python3 instead of python.
